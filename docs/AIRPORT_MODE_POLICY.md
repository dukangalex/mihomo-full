# 机场覆盖模式行为规范

## 定位

`airport_overwrite.js` 是 Mihomo-Full 的“纯机场模式”实现：机场节点直接连接目标，不使用自建 VPS 落地或 `dialer-proxy` 链式能力。

它必须与 `template.yaml` 保持**公共行为一致**，但保留机场模式自己的策略组和用户体验。

## 一致的公共行为

以下内容以 `template.yaml` 为基准同步：

- TUN 基础行为
- DNS
- Sniffer
- Hosts
- Rule Providers
- Rules
- Sub-rules
- GeoX / GeoData
- 通用运行参数
- 日志、连接、Profile、NTP、实验性参数等

## 有意保持差异的内容

### 1. 策略组

机场脚本保留原有地区、自动选择、负载均衡、手动选择、流媒体、漏网之鱼等策略组，不由同步器重命名或重构。

### 2. 广告拦截

保留：

- `REJECT` / `REJECT-DROP`
- `DIRECT`

默认应使用 REJECT。只有当某些免费内容网站依赖广告维持运营，并因拦截出现页面无法打开、视频无法播放、登录/功能异常等情况时，才临时选择 `DIRECT`。

不建议为了“少广告”长期关闭拦截，也不要把钓鱼/恶意域名加入广告直连例外。

### 3. 远控工具

保留现有默认策略，同时允许用户选择 `DIRECT`。适用于远控、P2P、内网穿透等工具与 TUN/代理发生兼容性问题的场景。

`DIRECT` 是用户主动选择的局部例外，不代表全局允许绕过 Mihomo。

### 4. 私有网络

私有地址、回环地址、链路本地地址等属于本机/局域网拓扑，不应送往机场节点。应通过底层规则直接处理，而不是额外提供一个全局“私有网络代理”按钮。

### 5. 国内服务

国内服务优先依据规则集和 CN IP 判定走 `DIRECT`。未知目标不能因为缺少国内分类而默认直连；无法可靠判定为国内时，继续遵循项目的安全默认路径。

### 6. 节点协议

机场模式**不按协议名称自动排除节点**。VMess、Shadowsocks、Trojan、VLESS、Hysteria/Hysteria2、TUIC 等均保留。

协议名称本身不足以准确判断实际安全性；服务端配置、加密/传输方式和节点来源同样重要。

## 同步安全规则

`tools/sync-airport-overwrite.py` 只同步公共行为，禁止：

- 重写机场策略组
- 删除广告组的 `DIRECT`
- 删除远控组的 `DIRECT`
- 添加协议排除
- 把链式 VPS/dialer-proxy 复制到机场模式

因此以后修改 `template.yaml` 时，机场脚本可以自动继承公共行为更新，同时不会破坏机场模式既有功能。
