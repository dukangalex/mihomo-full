# IPv6 策略与开关说明

本文件回答一个常见问题：**落地 VPS 没有 IPv6 出口时，配置里的 IPv6 双栈支持还要不要开？**

## 1. 两个互相独立的维度

IPv6 在本项目里其实涉及两件不同的事，容易被混为一谈：

1. **客户端本机网络是否有 IPv6**（手机运营商网络、家宽、Wi-Fi 出口等）——
   决定要不要在 TUN 层拦截并接管 IPv6 流量，属于**防泄漏**范畴。
2. **落地 VPS 出口是否有 IPv6**（仅链式模式相关，机场模式不受影响）——
   决定链式代理的最后一跳能不能用 IPv6 连到目标网站，属于**可达性**范畴。

这两者不是一回事：VPS 没有 IPv6，不代表客户端所在网络也没有 IPv6。判断要不要关闭配置里的 IPv6 支持，应该看**第 1 点**，而不是第 2 点。

## 2. VPS 没有 IPv6 时会发生什么

链式模式下，如果落地 VPS 只有 IPv4 出口：

- 目标网站如果是**双栈**（同时有 A 和 AAAA 记录，绝大多数网站都是），客户端解析到的 fake-ip 对应关系不受影响，连接最终仍会走 VPS 的 IPv4 出口正常访问，没有影响。
- 目标网站如果**只有 IPv6 地址**（现实中比例很低），链式代理最后一跳会因为 VPS 没有 IPv6 出口而连接失败。**这是安全的失败**（连不上，不会泄露），不是漏洞，只是这一小类目标暂时不可达。

也就是说，VPS 没有 IPv6，最多是"极少数纯 IPv6 站点连不上"，不会导致流量绕过代理。

## 3. 为什么即使 VPS 没有 IPv6，客户端侧的 IPv6 支持通常也应该保持开启

本配置从 PATCH 版本升级到 v6 时，专门把 `tun.inet4-route-only` 从 `true` 改成了 `false`（见 `template.yaml` 头部变更记录第 6 条）。原因是：

如果 TUN **只**接管 IPv4 路由，而客户端所在网络本身有原生 IPv6（大陆手机/家宽双栈很常见），那么设备上任何走 IPv6 路径的流量会**完全绕过 TUN、绕过所有分流规则**，直接裸奔到公网——这是真正的泄露风险，且与 VPS 有没有 IPv6 无关，纯粹取决于客户端本机网络。

所以结论是：

> **只要客户端本机网络可能存在 IPv6，就应该保持配置里的 IPv6 支持开启**，哪怕落地 VPS 只有 IPv4 出口。开着的代价只是"极少数纯 IPv6 站点通过链式代理连不上"；关掉的代价是"客户端 IPv6 流量可能完全脱离代理直连"，两者不对等，默认应该选前者。

## 4. 什么情况下可以关闭 IPv6 支持

只有一种场景值得关闭：**客户端设备所在的网络本身完全没有 IPv6**（很多大陆移动数据网络、部分老旧宽带仍然是纯 IPv4）。这种情况下：

- 配置里的 IPv6 机制（`fake-ip-range6`、`dns.query-v6` 等）永远不会被触发，纯粹是空跑；
- 每次域名解析会多发一次 AAAA 查询，等待其超时或返回空结果，增加一点点解析延迟；
- 关闭后没有任何功能损失，因为原本就没有 IPv6 流量需要保护或路由。

**VPS 没有 IPv6，不构成关闭客户端 IPv6 支持的理由**——除非客户端那一侧同时也没有 IPv6。

## 5. 如何判断客户端网络是否有 IPv6

在客户端设备的浏览器里访问：

- https://test-ipv6.com
- https://ipv6.google.com

任意一个能正常打开且显示到了 IPv6 地址，说明客户端网络有 IPv6，按第 3 节建议保持开启。都打不开或提示不支持，说明客户端没有 IPv6，可以按第 6 节关闭。

## 6. 关闭 IPv6 支持的操作步骤（`template.yaml`）

只需要改 **4 个开关**，IPv6 使用与 IPv4 相同的官方 `cn-ip` / `private-ip` MRS 规则集，不再维护不存在的 `geoip6/` 规则集——客户端没有 IPv6 流量时这些规则不会被匹配到，留着不会造成任何副作用，也符合"只增强、不削减既有功能"的原则，以后要重新开启时更省事。

| 位置 | 当前值（开启） | 改为（关闭） |
| --- | --- | --- |
| 顶层 `ipv6:` | `true` | `false` |
| `tun.inet4-route-only:` | `false` | `true` |
| `dns.ipv6:` | `true` | `false` |
| `dns.query-v6:` | `true` | `false` |

改完后重新生成配置：

```bash
mihomo-full --generate
```

（机场模式使用 `tools/sync-airport-overwrite.py` 会自动把这四项同步进 `airport_overwrite.js`，同步前后都建议跑一次 `--check` 确认无误。）

## 7. 重新开启 IPv6 支持

把上表 4 项改回开启值即可，无需其他改动。

## 8. 机场模式（方案 B）不受本节影响

纯机场模式下没有自建 VPS 落地，落地出口的 IPv6 能力完全取决于机场节点自身，与本机 VPS 是否有 IPv6 无关。第 1～5 节关于"客户端本机网络是否有 IPv6"的判断逻辑同样适用于机场模式；第 6 节的开关同样通过同步工具应用到 `airport_overwrite.js`。
